# 注文が来たときにやること

**0〜3件の規模では手渡しでよい。** 自動化は件数が正当化してから。
いま必要なのは「注文が来たときに詰まらないこと」だけである。

## 手順（1件あたり5分）

```
cd ~/side-projects/jftc-actions
git pull
npm run build:bundle          # build/enforcement-bundle.zip が出る
```

`npm run build:bundle` は**そのときの最新データで作り直す。**
月次の refresh で件数が増えているので、**古い zip を使い回さない。**

1. **中身を確認する** — 出力に件数と出典数が出る。`512 件 / 出典 181 件` のような行
2. **注文Issueに、件数と収録範囲を書いて返す**（後述の定型文）
3. **請求する** — 決済が通っていない間は個別対応。**Owner の口座情報を公開面に出さない**
4. **入金を確認してから渡す**
5. **Issue を閉じ、`docs/DECISION.md` の観測ログに1行足す**（注文日・用途・成約の有無）

## 返信の定型文

```
ご注文ありがとうございます。

内容を確認しました。現在のバンドルは以下です。

- 全 NNN 件（景品表示法 NNN / 独占禁止法・取適法 NNN）
- 期間 YYYY-MM-DD 〜 YYYY-MM-DD
- 出典URL NNN 件
- ファイル4点（統合CSV / 出典一覧 / 商用利用確認書 / README）

先にお伝えしておくことが2つあります。

1. 同じ元データは無料で公開しています。JSON で足りる場合は、そちらをお使いください
2. 課徴金額は全件収録していません。公表されている一覧表に金額の列が無く、
   年によっては画像内の表にしか存在しないためで、OCR で読んで事実として出すことはしていません

そのうえで必要でしたら、お支払い方法をご案内します。
```

**1と2を毎回書く。** 買ってから気づかれるより、買う前に断られたほうがよい。

## 決済が通ったあと

**注文Issue のテンプレートを購入リンクに差し替える。** そのときまで、この手順が経路である。

**自動化しない判断**：受け渡しを GitHub の collaborator 招待や署名付きURLで自動化できるが、
**注文が0件のうちに作ると、使われないものを作ることになる。**
件数が5件を超えたら考える。
